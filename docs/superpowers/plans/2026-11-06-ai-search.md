# AI Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a frontend-only "AI Search" page that turns a free-form request into keywords with the browser's on-device Prompt API, then ranks the whole library by weighted keyword match, optional empty room for text, and rating.

**Architecture:** Pure scoring and measurement modules under `src/services/aiSearch/`, a pipeline module that fans out one `/api/search` call per keyword, a support hook that gates the nav entry and route, and one page component that keeps request, keywords and options in the URL. No Worker, D1 or agent changes.

**Tech Stack:** React 19, Vite, Mantine, react-query, react-router, vitest + Testing Library, browser `LanguageModel` (Prompt API).

**Spec:** `docs/superpowers/specs/2026-11-06-ai-search-design.md`

## Global Constraints

- Frontend only: no change under `worker/`, `agent/`, `functions/` or `worker/migrations/`. `/ingest/*` and tokens untouched.
- Route `/ai-search`, nav label `AI Search`. The nav entry and route exist only when `LanguageModel` exists and its availability is not `unavailable`. Unsupported browsers: no nav entry, route redirects to `/`. No typed-keywords fallback for unsupported browsers.
- One search per keyword: `workerApiClient.searchPage({ q: <keyword>, sort: 'rating', limit: 100 })`. Keyword weight = `ln(libraryTotal / keywordTotal)`; library total from `searchPage({ limit: 1 }).total`. Keywords with `total` 0 are skipped.
- Pipeline order: per-keyword searches, union and keyword score, drop people photos (if on), keep top 150 by keyword score, measure empty space, final rank, show top 48. No paging.
- Final rank = `1.0 * keywordNorm + 0.6 * textSpace (only when leaveRoom) + 0.15 * rating/10`. `keywordNorm` = keyword score divided by the maximum in the candidate set. Rating = `combinedScore ?? aestheticScore ?? 0`.
- Empty space: 48 by 48 canvas, edge density in the top, bottom, left, right 40 percent bands, `score = max(0, 1 - meanEdge / 25)` of the calmest band. Constant `EDGE_BUSY = 25` is exported and easy to tune. Cache per thumbnail URL for the session.
- Options default on: Hide people photos, Leave room for text. URL keys: `q` (request), `kw` (comma separated keywords), `people=0` and `room=0` to turn options off.
- Model prompt: occasion name first plus alternate names, then symbols, then colour and light words, then generic subjects; single or two-word phrases; never people, gods or faces; schema-constrained JSON with a regex fallback.
- Style: no em dashes anywhere in code, docs or copy. Follow existing Mantine look.
- Work in a worktree at `.claude/worktrees/ai-search` on branch `ai-search`. Never push or merge to `main` (pushing deploys). Do not bypass the pre-commit hook. Docs (README, AGENTS.md, docs/architecture.md) land in the last commit, which is the same PR as the feature.

## Review Focus

- Every keyword has 0 matches, or all hits get weight 0: show an empty state that suggests editing keywords, never NaN/Infinity scores.
- A model reply wrapped in prose, with duplicates, mixed case, or a keyword containing a comma: parsed to clean unique lowercase keywords or a clear error.
- One keyword search fails (network or 5xx) while others succeed: results still show, the failed keyword is reported; if all fail, show an error.
- A thumbnail fails to load or the canvas read throws: that photo scores 0 space with no crash, and the others still rank.
- Rapid re-search or editing keywords while a search is in flight: the older response never overwrites the newer one.

### Task 2: Empty-space measurement

**Files:**
- Create: `src/services/aiSearch/textSpace.ts`
- Test: `src/services/aiSearch/__tests__/textSpace.test.ts`

**Interfaces:**
- Produces:
  - `EDGE_BUSY = 25`, `type Side = 'top' | 'bottom' | 'left' | 'right'`, `interface TextSpace { side: Side; score: number }`
  - `textSpaceFromLuma(luma: ArrayLike<number>, size: number): TextSpace` (pure; `luma` is `size*size` row-major; gradient `|L(x+1,y)-L(x-1,y)| + |L(x,y+1)-L(x,y-1)|` on interior pixels; band width `round(size*0.4)`)
  - `measureTextSpace(url: string): Promise<TextSpace>` (loads the image, draws to a 48 by 48 canvas, converts to luma `0.3R+0.59G+0.11B`, calls `textSpaceFromLuma`; caches by `url`; on any load or canvas error resolves `{ side: 'top', score: 0 }` and does not cache the failure)

### Task 6: AI Search page

**Files:**
- Modify: `src/components/AiSearch.tsx`
- Test: `src/components/__tests__/AiSearch.test.tsx`

**Interfaces:**
- Consumes: `expandRequest`, `Expansion` (Task 3), `normalizeKeywords` (Task 1), `runAiSearch`, `AiSearchResult`, `RankedPhoto` (Task 4), `usePromptApiSupport` (Task 5), `PhotoCard` (existing, used with its `footer` prop).
- Produces: page at `/ai-search` with URL state `q`, `kw`, `people`, `room`.

Page behaviour:
- Request textarea plus a **Find photos** button. Clicking it calls `expandRequest` (via `useMutation`), shows a status line fed by `onStatus` with elapsed time and the text "Running on this device", then writes the resulting keywords to `kw`, which triggers the search.
- Switches: **Hide people photos** and **Leave room for text** (default on; off writes `people=0` / `room=0`).
- Editable keyword box bound to `kw` with a **Search again** button that updates `kw` without calling the model. Below it: keywords with zero matches listed as "no matches", failed keywords flagged.
- Results via `useQuery` keyed on `['ai-search', terms, hidePeople, leaveRoom]` (stale responses cannot overwrite newer ones because the key changes). Results render in a grid of `PhotoCard` with a `footer` showing `matched: <hits>`, `Text space: NN% (side)` when measured, and the rating.
- States: model error shows the message and leaves the keyword box empty and editable; no results shows an empty state suggesting editing keywords; search error shows the message.
- A visit with `kw` in the URL searches immediately without calling the model.
